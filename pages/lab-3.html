Security Lab 03

Prototype Pollution

Explore unsafe JavaScript object merging and compare vulnerable and protected behavior.

CWE-1321 JavaScript Security Interactive Lab 03

01. The Vulnerability

Prototype Pollution occurs when untrusted keys such as __proto__ modify properties inherited by other JavaScript objects.

Here, settings and user share a prototype. An unsafe merge may affect user without changing its own properties.

02. The Vulnerable Code

This key excerpt from the team's unsafeMerge() follows inherited properties:

lab-3.js — unsafeMerge() excerpt Vulnerable 
target[key] = target[key] || {};
unsafeMerge(target[key], source[key]);

Security Issue: Without filtering dangerous keys, recursion can write to a shared prototype.

04. Why It Matters

Polluted inherited values may change application logic and potentially contribute to authorization bypasses or other unintended behavior.

05. The Fix

The team's safeMerge() rejects dangerous property names and safely creates nested objects.

lab-3.js — safeMerge() excerpts Fixed 
if (blockedKeys.has(key)) {
    continue;
}
// When a new nested object is needed:
target[key] = Object.create(null);

Security Improvement: Filtering __proto__, constructor and prototype prevents these payloads from changing the shared prototype.
