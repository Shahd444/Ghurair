Security Lab 01

IDOR Vulnerability

Learn how missing authorization checks can expose another user's information.

OWASP A01: Broken Access Control CWE-639 Interactive Simulation

01. The Vulnerability

Insecure Direct Object Reference (IDOR) occurs when an application allows users to access resources by changing an identifier without checking whether they are authorized to access those resources.

In this simulation, Alice is the authenticated user. The vulnerable application allows her to retrieve other users' profiles simply by changing the requested profile ID.

02. The Vulnerable Code

The application retrieves a profile using a user-controlled ID without checking ownership.

vulnerable.js Vulnerable 
const currentUser = { id: 1001 };
const profiles = getProfiles();
function getProfile(requestedId) {
  const id = Number(requestedId);
  if (!Number.isInteger(id)) {
    return { status: 400 };
  }
  const profile = profiles[id];
  if (!profile) {
    return { status: 404 };
  }
  return { status: 200, profile };
}

Vulnerable line: The profile is selected using the supplied ID without verifying that it belongs to the authenticated user.

04. Why It Matters


        

          IDOR can expose private records, personal
          information, and resources belonging to other
          users. Depending on the application, it may
          also allow unauthorized modifications.
        

      


      

        
05. The Fix


        

          The application must verify that the requested
          resource belongs to the authenticated user
          before returning it.
        


        

          

            fixed.js
            
              Fixed
            
          


          
const currentUser = { id: 1001 };
const profiles = getProfiles();
function getProfile(requestedId) {
  const id = Number(requestedId);
  if (!Number.isInteger(id)) {
    return { status: 400 };
  }
  if (id !== currentUser.id) {
    return { status: 403 };
  }
  const profile = profiles[id];
  if (!profile) return { status: 404 };
  return { status: 200, profile };
}

        


        

          Fixed line:
          The authorization check rejects requests for
          profiles that do not belong to the current user.
