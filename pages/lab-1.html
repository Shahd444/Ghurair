IDOR Vulnerability

Learn how changing a resource identifier can expose another user's record when the server does not verify ownership.

01. The Vulnerability

Insecure Direct Object Reference (IDOR) occurs when an application accepts a user-controlled resource identifier but fails to check whether the signed-in user is allowed to access the resource.

Changing an ID in a URL, JSON request body, or Base64-encoded reference must never bypass server-side authorization.

03. Why It Matters

An IDOR flaw can expose sensitive records or allow unauthorized changes. Parameter encoding does not provide authorization; the server must check permissions for each resource and request.

04. The Fix

Use authenticated session identity to check resource ownership before returning data. The Fixed mode above simulates this check and returns HTTP 403 for another user's record.

Essential ownership checkFixed
if (record.owner_id !== req.session.user_id) {
  return res.status(403).json({ error: "Forbidden" });
}

Security Improvement: A resource-level ownership check protects all three request parameter formats.
