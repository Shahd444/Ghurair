Security Lab 01

Insecure Direct Object Reference (IDOR)

Explore how a missing ownership check can expose someone else's payroll record, and learn how server-side authorization blocks it.

CWE-639 Broken Access Control Interactive Lab 01

01. The Vulnerability

IDOR occurs when an application uses a user-supplied identifier to access a resource without checking whether the signed-in user is authorized to view it.

This demonstration uses payroll record 1001 as your own record. In Vulnerable mode, requesting another employee's identifier reveals their data. In Fixed mode, the same request is denied.

03. Why It Matters

Missing authorization checks can expose another user's payroll information, profile, orders, or documents even when the attacker is authenticated.

04. The Fix

Every resource request must verify that the authenticated user has permission to access the requested record. Base64 encoding or hiding IDs does not replace authorization.

const record = findPaySlip(id);
if (!record) return res.sendStatus(404);
if (record.owner_id !== req.session.user_id) {
  return res.sendStatus(403);
}
return res.json(record);

Security improvement: Check the record's ownership on the server before sending the response.
